# stat.service

Локальный планер-приложение для учёта привычек и прогресса по проектам. Данные хранятся **на сервере** в SQLite: у каждого пользователя отдельный файл. С телефона и с компьютера — один аккаунт, одни и те же проекты и отметки.

## Функционал

### Проекты
- Создание календарных проектов с названием, описанием и флагом **«Изменяемый»**.
- Если проект не изменяемый, отметки в календаре можно только ставить — снять их нельзя (даже администратору).
- Календарь с отметками дней, черновым режимом редактирования («Добавить отметки» → «Готово» / «Отменить»).
- Заметки к отдельным дням.
- Статистика проекта: отметки за месяц, текущая и лучшая серия.
- Удаление проекта (с подтверждением паролем) в настройках страницы проекта.

### Дашборд
- Сводная статистика по всем проектам: количество проектов, отметки, серии, достижения.
- Таблица проектов с переходом на страницу проекта.
- Блок «Последние полученные достижения».

### Достижения
- Система достижений за серии, количество проектов, заметки, выходные, прогресс месяца и др.
- Страница со списком всех достижений (полученные и неполученные).
- Праздничная анимация при получении: модальное окно, конфetti, кнопка **«Я МОЛОДЕЦ»**.

### Пользователи
- Регистрация и вход по email/паролю.
- Первый администратор создаётся автоматически из переменных окружения (см. ниже).
- Администратор может снимать отметки в **изменяемых** проектах; обычный пользователь — только добавлять.

### Интерфейс
- Тёмная и светлая тема.
- Адаптивная вёрстка для мобильных и десктопа.
- Боковое меню: Дашборд, Проекты, Достижения.

## Технический стек

| Слой | Технологии |
|------|------------|
| UI | React 19, TypeScript, React Router 7 |
| API | Node.js, Express, better-sqlite3 |
| Сборка | Vite 8 |
| Стили | CSS (кастомные), Tailwind (частично) |
| База данных | SQLite на сервере |
| Деплой | Docker (nginx + API), volume `/data` |
| Иконки | Lucide React |

Фронтенд — SPA, все операции идут через REST API (`/api/*`). Сессия — httpOnly cookie (JWT).

## Быстрый старт

### Локальная разработка

```bash
cp .env.example .env

# API (терминал 1)
cd backend && npm install && npm run dev

# Фронтенд (терминал 2)
cd src && npm install && npm run dev
```

Vite проксирует `/api` на `http://127.0.0.1:9000`. API сохраняет данные в `backend/data/`.

### Docker

```bash
cp .env.example .env
# отредактируйте .env: JWT_SECRET, VITE_SEED_ADMIN_*
docker compose up --build
```

Приложение будет доступно на `http://127.0.0.1:3000`. Данные — в Docker volume `stat_data` (`/data` в контейнере API).

## Первый пользователь

Первый администратор создаётся **автоматически при старте API**, если база учётных записей пуста:

```env
VITE_SEED_ADMIN_EMAIL=admin@local
VITE_SEED_ADMIN_PASSWORD=change-me
```

Порядок действий:

1. Скопируйте `.env.example` → `.env` и задайте email, пароль и `JWT_SECRET`.
2. Пересоберите/перезапустите (`docker compose up --build`).
3. Войдите на `/login` с указанными учётными данными.

Важно:

- Seed срабатывает **только один раз** — когда в `auth.sqlite` ещё нет пользователей.
- Создаётся пользователь с флагом **администратора** (`is_admin = 1`).
- Если seed не настроен, можно зарегистрироваться вручную на `/register` (будет обычный пользователь, не админ).

Имя приложения в интерфейсе задаётся переменной:

```env
VITE_APP_NAME=stat.service
```

## Где хранится база данных

Все данные на **диске сервера** в каталоге `/data` (Docker volume `stat_data`):

| Файл / каталог | Назначение |
|----------------|------------|
| `/data/auth.sqlite` | Учётные записи (email, хеш пароля, is_admin) |
| `/data/users/{id}.sqlite` | Проекты, отметки, заметки, достижения пользователя |

Пример:

```text
/data/
├── auth.sqlite
└── users/
    ├── 1.sqlite
    ├── 2.sqlite
    └── 3.sqlite
```

Один пользователь = один файл. Вход с Safari на телефоне и Firefox на ПК — **одни и те же данные**, потому что они на сервере.

### Бэкап и перенос на другой сервер

Скопируйте весь каталог `/data`:

```bash
# бэкап
docker run --rm -v stat_data:/data -v $(pwd):/backup alpine \
  tar -czf /backup/stat-data-$(date +%F).tar.gz -C /data .

# восстановление на новом сервере
docker run --rm -v stat_data:/data -v $(pwd):/backup alpine \
  tar -xzf /backup/stat-data-YYYY-MM-DD.tar.gz -C /data
```

После восстановления задеплойте приложение с тем же `.env` (или перенесите `JWT_SECRET`, иначе старые сессии в cookie не сработают — пользователям нужно войти заново).

### Локальная разработка без Docker

По умолчанию API пишет в `DATA_DIR` (можно задать в окружении). Для dev удобно:

```bash
export DATA_DIR=./data
cd backend && npm run dev
```

## Переменные окружения

| Переменная | Описание |
|------------|----------|
| `VITE_APP_NAME` | Название в интерфейсе |
| `VITE_SEED_ADMIN_EMAIL` | Email первого администратора (передаётся в API) |
| `VITE_SEED_ADMIN_PASSWORD` | Пароль первого администратора |
| `VITE_API_BASE` | Базовый URL API (по умолчанию `/api`) |
| `JWT_SECRET` | Секрет подписи JWT-сессий (API) |
| `DATA_DIR` | Каталог данных на сервере (по умолчанию `/data`) |
| `TZ` | Часовой пояс API (IANA, напр. `Europe/Minsk`). Влияет на «сегодня» в календаре и статистике |
